# 한국어 PR 템플릿

한국어 프로젝트에 사용한다. 아래 "제목 규칙"과 "본문 템플릿"을 따른다. 꺾쇠(`<...>`)와 HTML 주석은 실제 내용으로 바꾸거나 지운다.

## 제목 규칙

`<type>: <한국어 요약>`

- type: `feat`, `fix`, `refactor`, `chore`, `docs`, `test` 중 PR 전체를 대표하는 하나.
- 요약은 간결한 서술, 70자 안팎, 마침표 없음. 예: `feat: 프롬프트 500자 제한 검증 추가`
- 코드 식별자와 기술 용어는 원문 그대로 쓴다.
- 커밋이 하나뿐이면 그 커밋 제목을 그대로 써도 된다.

## 본문 템플릿

```markdown
## 요약

<이 PR이 무엇을 바꾸는지 1~3문장. 커밋 목록이 아니라 전체 흐름으로 쓴다.>

## 변경 사항

- <주요 변경 1>
- <주요 변경 2>

## 변경 이유

<왜 필요한 변경인지. 배경, 해결하려는 문제, 선택한 방식의 이유. 요약만으로 충분하면 한 줄로 쓴다.>

## 테스트

- [ ] <실행한 테스트 명령과 결과 (예: `bun run test` 통과)>
- [ ] <수동으로 확인한 시나리오>

<실행하지 않은 항목은 체크하지 않고 이유를 적는다.>

## 리뷰 포인트

<리뷰어가 중점적으로 볼 부분, 트레이드오프, 알려진 한계. 없으면 "해당 없음".>

## 관련 이슈

<Closes #번호. 없으면 이 섹션을 지운다.>

🤖 Generated with [Claude Code](https://claude.com/claude-code)
```
